# 2048

Status: MVP implementation on `agent/game-2048`. This document records the
product and design decisions for the game. Platform-wide rules for any new
game are in [rules for adding a game](../new-game-rules.md).

## Identity

- Public title: **2048**.
- Game id: `2048`. Route: `/games/2048`.
- Package: `@aviarium/game-2048`.
- Theme class: `twenty48-theme` (the id cannot be used as a CSS class).
- Tags: Logic, Numbers, Sliding.
- Input: keyboard, pointer, touch. E-reader: supported.
- The game is a full library game: library card, game menu, Continue, History,
  leaderboards, guide, and offline install. There is no hero slide in the MVP.

## Player-facing rules

- Board: classic 4 × 4.
- Goal: create a tile with the value 2048.
- Start: two tiles on distinct random cells; each is 2 (90%) or 4 (10%).
- A move slides every tile as far as possible in one direction. Equal adjacent
  tiles merge once per move; the merged tile's value is the sum. The move only
  counts if at least one tile moved or merged.
- After a counted move, one new tile appears on a random empty cell: 2 (90%) or
  4 (10%). A move that changes nothing does not spawn a tile.
- Score: the sum of every merge (2 + 2 = 4 adds 4; 64 + 64 = 128 adds 128).
  Starting tiles add nothing. There are no bonuses.
- Reaching 2048 does not end the run. It records the time at which the first
  2048 tile appeared, shows a celebration with the time and score, and offers
  **Keep playing**.
- The run ends when no legal move exists: the board is full and no two
  orthogonally adjacent tiles are equal. That is a completed attempt with a
  final score and a game-over screen.
- A player may leave a run unfinished and resume it later. There is no undo, no
  timer display, no move limit, and no time limit in the MVP. Elapsed time is
  recorded for history and for the 2048 time milestone.
- A new game creates a new save and a new seed. The platform's save cap and
  Continue list apply as they do to other games. The player manages their own
  saves.
- The game is account-based, like the rest of Aviarium. There is no separate
  guest score.

## Seed and generation

- The seed determines the starting board and every subsequent tile spawn. The
  same seed plus the same sequence of moves produces the same board, score, and
  2048 time across devices, offline, and the server.
- The generator version is stored on the level. Version 1 is the initial
  implementation.
- The save stores the move directions, score, board, elapsed time, and the time
  the first 2048 tile appeared. The server replays the moves from the seed to
  verify the board, score, 2048 milestone, and game-over state. This makes a
  score leaderboard possible without trusting a client-reported number.
- A seed is a short string. The menu hides the seed field until **Enter seed**
  is selected; an empty field or the normal **New game** button creates a random
  seed. The play screen does not show the seed. The seed code is visible where
  it is useful, such as a leaderboard result, rather than during play.
- After game over, **Play again** creates a new seed. There is no "same seed"
  button in the MVP.
- The 30-day cooldown is per exact starting board. A repeat of the same seed
  inside the window is saved but is not posted as a new visible top result.
  This is the same rule as the other games.

## Scores and leaderboards

- A completed run always produces a score result, whether or not the player
  reached 2048. `unit = 'score'`, higher is better.
- The MVP has one score board: **Classic** (4 × 4). It groups results across
  seeds; the exact seed is stored on each result for the cooldown and for
  "play this board". This matches the way Quick Play boards group by settings
  while the exact puzzle remains a cooldown key.
- The 2048 time is recorded and shown on the milestone and the game-over card.
  A **fastest 2048** leaderboard is a follow-up. It needs a second result from
  one attempt; the platform currently writes one result per completed attempt,
  so it will be added as a platform capability rather than a game hack.
- A personal best is the highest score among the player's completed 2048 runs.
  The game shows it in the header and on the game-over card. A new best gets the
  celebration treatment; a lower score does not.
- The leaderboard link, "Your best" strip, moderation, cooldown, avatars, and
  removal notice are the shared platform flows. The game does not add a table
  or a route.

## Daily challenges

2048 declares `generation` and `leaderboard`, so the platform derives it as a
challenge-capable game. The admin can select it for a daily challenge using the
normal game-selection flow. It is **not** in the existing default rotation:
that rotation is stored in `challenge_series.game_selections`, so adding the
game does not silently replace today's Sudoku or Nonograms slot.

A 2048 daily challenge uses the game's normal generation and score result. The
platform's score unit is used end to end: higher is better, and the score is
formatted as a number rather than a time. A challenge is one attempt, ends at
the normal reset boundary, and posts the completed run. The game does not own a
challenge scheduler or a challenge route.

## Screens and interactions

- **Game menu**: Continue for an unfinished run, a Quick Play panel with a
  **New game** button, a **Play a seed** destination, How to play, History, and
  Leaderboard. No pack section and no Studio. The seed review screen carries
  the generator version and played options.
- **Play screen**: full dynamic viewport, no page scrolling. Tile movement is
  180 ms and the merged value is revealed only when the sliding tiles meet,
  rather than at the start of the move. The merged tile shrinks slightly and
  bounces with a 320 ms pop. The score updates immediately, but the new tile
  appears in the last tenth of the slide so its cell is clear. A compact header
  with Back, the game name, Score, and Best. The seed is not shown during play;
  it is available from the game menu when a player needs it. The 4 × 4 board
  fills the available space. The board is keyboard-focusable; arrow keys and
  WASD move, and swiping moves on touch. Focus never leaves the game on a
  direction key.
- **2048 milestone**: a celebratory result card with the achieved time as the
  primary value, the current score, and **Keep playing**. The copy is
  upbeat: reaching 2048 is an achievement, and the run continues for a higher
  score.
- **Game over**: a result card with the final score as the primary value, the
  personal best and a "New best" badge when applicable, the time, highest tile,
  and move count. Actions:
  **Play again** (new seed), **Back to menu**, and **View leaderboard**. A new
  personal best can use the budgie flock/confetti; an ordinary loss does not.
- **History**: every completed 2048 run is listed with its score, date, and a
  replay action for the same seed. The existing history screen derives this
  from completed saves.
- **Continue**: an unfinished run shows its current score and highest tile.

## Theme and art

- Light palette: warm parchment page, cream surface, honey/amber accent, dark
  brown text, toasted beige empty cells. Tile values climb from cream to gold;
  2048 and above use a deep amber with light text.
- Dark palette: near-black brown page, dark cocoa surface, gold accents, warm
  cream text. Empty cells are dark cocoa; tiles use the same gold ramp.
- Reader mode: grayscale, high-contrast numbers, no color-only information, and
  no slide/pop motion. Tile values, not colors, communicate the board.
- A parrot is the mascot. The library preview is a tile board with a small
  stylized parrot; the existing budgie celebration is reused for a new best or
  the 2048 milestone. No new audio.
- The game credits the original 2048 by Gabriele Cirulli (MIT) in the About
  page and in the guide.

## Compatibility and non-goals

- No packs, no Studio editor, and no authored 2048 levels in the MVP. The game
  supplies empty pack schemas only because the shared contract requires them;
  the web catalog hides authoring for games without a Studio.
- No undo, no 5 × 5 or 3 × 3 boards, no target other than 2048, no daily seed
  outside the challenge system, no sound, no haptics, no hero slide.
- Old finished runs remain readable as history. A future generator version
  must not change the old seed meaning; it gets a new version and new levels.
- The score board's 30-day per-seed cooldown may be revisited once the fastest
  2048 board exists. For now it follows the established leaderboard rule.

## Verification scenarios

- Start a new game, make a move, reload, and resume the exact board and score.
- Type a seed, play the same moves on another device or in another browser, and
  confirm the same board and score.
- Reach 2048, confirm the milestone card shows the time and score, and continue.
- Fill the board without moves, confirm the game-over card, best score, new-best
  state, and a posted leaderboard result.
- Replay the same seed inside 30 days and confirm the result is saved as a
  cooldown rather than a second visible score.
- Compare two seeds on the Classic board; confirm scores rank higher-is-better
  and the seed chip opens the same board.
- Play with keyboard only, touch only, reader mode, reduced motion, and at phone
  and desktop widths.
- Go offline, finish a run, reconnect, and confirm the save and score sync.
- Check the History entry and the About credit.
